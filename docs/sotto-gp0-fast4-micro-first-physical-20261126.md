- **GPF1 valid**, exact module serial `1795751383`, successful GP0 capture start, module return **202** (positive encoded-frame count). `pcm_lost=false`; `gp0_dma_error=0`; `gp0_missed_halves=0`; `resource_errors=0`; `fsk_errors=0`. The `gp0_irq_count=65535` has **saturated** the 16-bit telemetry, so it means at least 65,535 handler completions, not an exactly measured count. Peak ISR `3147` TIM17 ticks.
- **GPT1 valid**: **43,342 codec resource reads**, **28 FSK preloads**, 2.2ms peak reported FSK preload callback, 258.24µs peak resource callback (TIM17 16-bit wrapping makes longer timings ambiguous), PCM backlog **2/4 blocks at stop**, partial queue offset 6 samples, no failure reason recorded. A 2-block value at shutdown is *not* the peak occupancy.
- This is a substantial change from the prior repeated physical **PCM queue full / return -12** test after ~2,182 DMA half-buffer IRQs. The optimized encoder ran to a positive completion and dekeyed normally. These counters do **not** verify that the analog microphone waveform reached the encoder with good SNR.

## Independent external SDR evidence and important attribution limitation

The live Sotto Monitor recovered CRC-valid `BEGIN`, `VOICE`, and `END` packets from the real RTL-SDR, but no byte-exact connection between individual received sessions and the radio module return timestamp has been independently established. **Do not call all these mic-originated solely from adjacent timestamps.** Two earlier sessions (19:50:23–19:51:00) contained 14 CRC-valid packets / 76 codec frames and decoded to approximately 3.04s of broadband-noisy audio (high-frequency 2.4–3.9kHz power >2.8x voice-band 0.1–1.4kHz power). The user independently heard static.

A later saved monitor export (19:54:21–19:55:08) had 70 CRC-valid packets, 429 codec frames, and six BEGIN/END sessions. **Five sessions were byte-identical 26-frame codec sequences**, consistent with the separately tested physical `SOTTO SYNTH` fixture; they decode to a clean ~315Hz tone when processed in one continuous decoder (high-frequency power negligible). A sixth, much longer session contained 299 different codec frames, with **298 first bytes equal to `0x13`**, and remained high-frequency noise dominated (>3x voice-band power) even after continuous per-session decoding. Its physical microphone provenance is **plausible but not proven** without a synchronized log. This A/B contrast shows that the physical RF→RTL-SDR→decoder path can deliver clean synthetic audio, while another actual captured stream carried noise-like codec content.

## Independent Sotto Monitor decoder bug found

The original monitor started a *fresh native decoder process* for every 66-byte radio packet. Sotto 1200 requires continuous synthesis state and **2 superframes of lookahead** across all packets in one session. On 76 actual recorded codec frames, correct continuous decoding gave only ~0.20 PCM waveform correlation with the previous per-packet-reset output. On the longer 429-frame export, correlation was only ~0.16. The decoder state reset is a real independent artifact, **but continuous decoding still left the long session broadband-noisy**.

The Sotto Monitor's *local* git main now contains commit `3108210` with `stream_decoder.py`, gap handling, and a persistent decoder process from BEGIN through END. **15/15 receiver regressions passed.** The running port8024 process **had not yet been restarted** because a separate active receiver session retuned to 433.5MHz and was recording packets; force-restarting or retuning would destroy someone else's active capture. When the live receiver can be safely stopped, restart to load the new module, preserving its last tuned RF frequency, 30.5/31.3kHz offset, and `SOTTO_RTL_IF_OFFSET_HZ=-250000` hardware IF setting.

## Next shortest discriminating physical experiment

Use the previously verified signal generator **1kHz, nominal 0.1V** microphone-jack injection (no programming cable concurrently), dummy-load TX at **443.500MHz**, and the installed slot24 GP0 module. Record live IQ (and the **exact SDR center and click-to-tune correction**, not assuming offset 0), decode continuously with native Sotto 1200, and calculate 1kHz-to-noise floor. Retrieve GPF1/GPT1 immediately on reconnect without cycling the radio. A clean 1kHz tone with noisy acoustic speech suggests mic gain/coupling/analog routing. A noise-dominated 1kHz transmission points to the GP0 PDM-to-PCM filter, scaling, and potential out-of-band aliasing. The current decimator is a fractional **boxcar** from ~87kHz density into 8kHz PCM with ~62Hz DC rejection; its stopband/noise behavior is insufficiently measured to rule out aliased PDM noise. Further codec trimming would be premature until this analog fidelity gate passes.
