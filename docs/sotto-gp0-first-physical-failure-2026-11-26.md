# First physical SOTTO GP0 TX: early abort and stage diagnostic

2026-11-26, K6 B-chip, dummy load, operator-held physical PTT, programming cable disconnected. The restored KUL2 firmware enumerated and launched SOTTO GP0 correctly. The optimized level30 module was installed and verified in logical slot24 (9700 code bytes, envelope SHA256 `f2728af95c090bab0478ebc04beed4fda16606c1b1088de7e12fc1bb81d57ac0`).

The operator observed no detectable RF and a PTT/TX LED lasting about one second, then immediate return to catalog. An RTL-SDR receiving 433.500 MHz nominal, digital correction -30.5 kHz, observed zero sync candidates, zero CRC-valid packets, and zero decoded PCM; SDR was healthy. The operator's actual VFO was not positively verified, so zero packets alone does not prove absence of RF. The TX LED is not RF proof: the module calls `tx_on()` in a PA-muted capture lease and FSK activity is only enabled later by `fsk_async`.

The code requires 800ms RFIC microphone-bias settlement after a successful physical PTT, then calls `mic_stream(8)` to start firmware-owned GP0/PB1 DMA1 IRQ9 PCM production. The early abort is consistent with GP0 start rejection or an immediate producer/codec stall; stage remains unproven until the operator retests with diagnostics.

A tiny branch-local stage diagnostic in `c/k6/mod/sotto_gp0_irq_tx.c` now prints `GP0 START FAIL` on `mic_stream(8)` refusal, otherwise `GP0 RUN ABORT` on later failure, retaining the LCD text for 2.5 s after calling both capture stop and `tx_off`. This was intentionally bounded to 44 added code bytes; resulting module 9744 B, scratch 4168 B against required 4080 B (88 B margin). Test run with `/home/tyler/.local/share/flux-rf-venv/bin/python -m pytest -q tests/test_k6_sotto_gp0_end_to_end.py tests/test_k6_sotto_module.py tests/test_k6_sotto_mic_gp0_irq.py tests/test_k6_sotto_api30_port.py tests/test_k6_sotto_gp0_pcm.py` returned **44 passed**. Note the host default Python lacks Unicorn and cannot run the virtual link suite; use the named venv.

Deployed the diagnostic envelope in logical slot24, radio protocol5; loader accepted 169/169 transfer chunks, readback verified entire 9768-byte envelope, and reverified slots25/30 unchanged. See release recovery evidence under `/storage5/dev/flux-sotto-gp0-kul2-verified-release-20261126/recovery/`. The previous optimized module is saved as `slot24-optimized-working-9700.k6m` for rollback; original pre-KUL2 module and complete SPI backup remain retained.
