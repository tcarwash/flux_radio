# GP0-to-Sotto firmware integration: trimmed, offline-qualified handoff

**2026-11-25, branch `feature/sotto-mic-continuous-pa-20261125`.**

## Real radio evidence (already captured, not repeated in this work)

- K6 B-chip RFIC microphone input responds to injected 1 and 2 kHz audio. GP0 selector 12 → MCU PB1 has stimulus-frequency-specific bit-density modulation. The installed `MIC PCM` diagnostic demonstrated **8 kHz signed PCM** with physical 1/2 kHz frequency tracking and an input-OFF noise control.
- The installed `MIC IRQ` diagnostic subsequently sustained live **DMA1 CH1, IRQ9** input and 8 kHz PCM production in a short attended run with simulated ~2 ms foreground work per 10 ms block: **6,826 DMA half interrupts, 5,006 samples, 62 consumed 80-sample blocks, peak 2,365 TIM17 ticks (~24.6 µs nominal), no missed halves, no PCM overflow, no clipping; maximum PCM backlog one block.** This is *not* real Sotto encoder/FSK concurrency.
- `MIC IRQ` remains installed in physical catalog slot **25**; previously confirmed `SOTTO MIC` in slot **30** is unchanged. This development handoff deliberately **does not flash or transmit**.

## Implementation and required fit

- `firmware/k6-aura/sotto-api30-gp0-capture.rs` owns the ~1 KiB raw GPIO DMA ring, interrupt handler/decimator, and GP0 capture state; the module supplies only its regular **644-byte, four-block Sotto PCM queue** via API30 `mic_stream(op=8, ptr, fs=87260)` after the separately guarded RFIC-only `op=7` microphone lease. IRQ9 is installed only while TXDOG SRAM remap is held. All exits stop DMA and clear module PCM/DMA pointers, restore vector/priority, and release RFIC microphone route through `op=1`/TX off.
- The DMA raw ring borrows the *1,024-byte, otherwise reserved* arena LCD callback-stack region; `op=8` refuses arena-backed module-stack or telemetry configurations. The Sotto GP0 module cannot safely use LCD callbacks while DMA is active. Its short startup UI is rendered **before** the TX lease; no LCD writes occur while capture is running. The firmware's production ISR is modeled on the physically qualified module-owned code but is distinct compiled Rust code.
- `c/k6/mod/sotto_gp0_irq_tx.c` is a separate, opt-in **`SOTTO GP0`** loadable module; it reuses the working Sotto encoder, packet queue and nonblocking FSK callback. Before starting GP0 DMA it enables the RFIC MICIN route, **waits 800 ms for ADC bias settling**, rechecks physical PTT, then requests `op=8`. The previous `SOTTO MIC` transmitter is not replaced.
- `tools/k6_sotto_module.py` measures the module against an arena of **14,976 bytes**, with **1,040 bytes callback-stack reserve** and 24 bytes image overhead. The settled GP0 module is **9,796 bytes**, the Sotto IVF resource deck **4,182 bytes**, the module's verified encoder+engine scratch requirement **4,080 bytes**, leaving **36 bytes scratch margin**. This is enough to pass the strict tool gate but is a *small* margin and must not be portrayed as generous.
- The firmware uses a stable API31 host tail but omits the **optional 4800-baud receiver** and other unneeded FSK RX settings for the TX-only profile. `apply-sotto-rx4800.py` still inserts the host ABI while `K6_FSK4800_RX=0`. The build script now applies `apply-user-store.py`'s read-only library-location helper whenever Sotto resources need it, without enabling the write-capable user-store feature. The full RX enabled experimental image previously needed **126,076 bytes** and exceeded the 122,880-byte application limit; the TX-only profile is **119,928 bytes**, leaving **2,952 bytes flash margin**. This net 6,148-byte reduction encompasses the RX and optional-FSK configuration differences; do not attribute all of it to any single change.
- The corresponding linked image uses **3,840/3,840 bytes protected RAM0**, **14,976-byte module arena**, and a **2,780-byte main-stack reservation** that passes the audit. RAM0 has **zero unallocated bytes** in this specific build; any further static state needs another trimming pass. The new decoder/IRQ service is not yet optimized or production qualified.

The linked ARM firmware passes the op7 lease/reentrancy/no-TIM17-IRQ/cleanup test.
- `tools/k6_sotto_gp0_irq_service_arm_gate.py` plus `tests/data/k6/sotto_gp0_irq_service_call_emu.c` verify the **actual linked ARM GP0 DMA IRQ start and cleanup** in the no-RX firmware: TX lease required; op7 mic lease, op8 with real module scratch, reentry rejection; GP0 selector12 and MICIN enabled; DMA1 CCR CHEN and 1,024-byte CNDTR active, SRAM IRQ9 vector installed, TIM17 cycle counter active, module PCM and raw DMA pointers nonzero/disjoint; after `op=1`, vector, PA, DMA and raw pointers are restored/cleared. - Existing TIM17/PA11 API30 linked-ARM sampler normal-stop and abandoned-module cleanup gates were adapted to recognize the valid TX-only API30 profile without weakening the API31/RX-enabled assertions. Previous native GP0 IRQ and PCM synthetic tests remain available.

## Unresolved before physical TX

1. **Encoder/FSK concurrent timing:** RFIC SPI flash codebook reads and nonblocking FSK FIFO/PA operations may mask or delay DMA IRQ9 servicing. The prior real `MIC IRQ` test only simulated 2 ms of foreground work, not true Sotto encoder/SPI/FSK processing; a linked ARM + virtual-RF/codec test and/or attended protected hardware timing check is still required.
2. **PCM input fidelity:** Injected 2 kHz input was substantially stronger than 1 kHz at nominally equal generator voltage; acquire longer bandwidth/real-speech PCM and characterize gain, filtering, clipping and audible output. No intelligible standalone Sotto speech is claimed.
3. **Memory margins:** 0 bytes RAM0 reserve and 36 bytes module scratch headroom mean new features should not be layered on this profile without further size optimization. Avoid dropping old PA11 support or RX features from *default builds* until compatibility is explicitly addressed. The RX-free profile is a deliberate **experimental TX-only variant**, not an across-the-board removal of receive support.
4. **Safety:** No automatic flash, real RF TX or slot30 replacement in this handoff. Any physical test should be bench-locked, on the known dummy load, with serial disconnected for microphone input, and should preserve the installed diagnostics and SPI backup.
