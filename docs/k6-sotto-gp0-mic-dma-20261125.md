# Sotto mic-to-MCU: GP0 selector12 5.5MS/s DMA spectrum probe (2026-11-25)

## Why this experiment

The RFIC microphone works and an awake 1kHz/0.1V injected source yields max RFIC VOX ~537 versus ~198 with output OFF. The external microphone therefore reaches the RFIC. Multiple physical PA11 experiments established that the existing PA11 one-wire sigma-delta sampler records only an initialization/RC transient: after 80-120ms the raw bitstream is near-static HIGH, regardless of injected microphone tone. `MIC ROUTES` confirmed that AF selectors 1/4/5/9 provide no sustained PCM through PA11, even when VOX confirms the mic tone. GP0→PB1 selector12 produced digital transitions but coarse 25.6ksample/s polling gave no frequency evidence. Previously published GP0 DMA experiments (`docs/k6-fd6818-audio.md`) showed a ~5.5MS/s bitstream, with hardware readout on PB1; selector 13 in RX was a ~17kHz IF, but its behavior in TX is different and no TX mic route is established.

## Fundamental TIM17 conflict and the fix

Existing `API30 mic_stream(0)` enables the RFIC microphone ADC (`REG_30` MICIN bit2) and also starts a **TIM17 interrupt-driven, PA11-active sigma-delta sampler**. The successful GP0 capture uses a free-running **DMA1 channel1 + TIM17 counter**; combining both existing samplers would corrupt the measurement and risk module ownership. Further, the normal `tx_on()` module lease sets `REG_30=0xC1FA` with the MICIN ADC disabled. Thus a GP0 DMA probe that merely enters TX and reads GP0 would not have a validated microphone feed.

The new **`mic_stream(op=7, ptr=NULL, n=0)`** callback option in `firmware/k6-aura/sotto-api30-mic.rs.inc` sets up precisely the existing audited *RFIC microphone route* without starting the PA11 sampler or claiming TIM17. Preconditions are the same API30 `tx_on` PA-muted lease, live UART excluded, FSK/FDIC ID, hardware watchdog, and no existing mic lease; it retains the existing `SOTTO_MIC_ROUTE` ownership flag and saved `[REG30,47,48,7D]`. `mic_stream(1)` or `tx_off()` restores everything via `sotto_mic_stop`, which already no-ops the PA11 stop when the PCM ring is inactive. It cannot be invoked outside a TX lease or while another mic route is active. Original `mic_stream(0)` behavior is untouched (the route-only predicate is false there).

Compiler-checked FD6818B opt-in firmware: image SHA256 **`751995d2dd346a2cfbf7503f8b4d722076cec9164a61efa495b3ca884dc67ccb`**, size **122,744/122,880 B** (136B margin), RAM0 used 3816/3840 (24B free), stack reservation 2792B. Build from the worktree with the exact opt-in parameters used in previous raw PA11 image, output `/tmp/flux-sotto-mic-20261125/fw-gp0-route-only-v1/flux-fd6818b-pack.bin`. A real linked Cortex-M0 emulator gate (`tools/k6_sotto_gp0_route_arm_gate.py`) passed the new op7 contract: rejected without TX lease, accepted with a PA-muted TX lease, rejected reentrant start and op0, observed RFIC REG30 MICIN enabled, **TIM17 counter and IRQ both inactive, PA11 ring pointer NULL**, successful mic route restoration and return 17. The existing Sotto mic→FSK→receiver ARM integration gate also passed with full CRC-valid packet recovery and PA restored. These are offline simulations, not physical GP0 audio verification.

## `MIC GP0` data module in Catalog slot25

`c/k6/mod/sotto_mic_gp0_dma.c` is the dedicated loadable API30 module, built separately from `MIC ROUTES`; **slot30 SOTTO MIC must remain untouched**. On entry, its UART result mailbox is invalidated with `MAB1:CLR`. It waits for physical PTT with programming cable disconnected, keys a **2.5-second TX lease with RF PA muted**, and calls `mic_stream(7)` to enable the RFIC microphone. It checks PB1 is a GPIO input and only enables GP0 by `REG_33` bit8, selects **GP0 selector12** via `REG_34[3:0]`, allows **800ms mic ADC/bias settling time**, and snapshots the register values **after TX began** (the earlier `MIC ROUTES` bug had captured TX LED state too early). No RF transmission; no normal RF PA enable; no SPI flash writes.

The module refuses TIM17 already enabled or DMA1 channel1 occupied, then saves/restores RCC AHB/APB2 clocks, TIM17 and DMA1 channel1. It uses the previously measured GP0 architecture (DMA reads GPIOB IDR into a 1024-byte circular ring at ~5.5M transfers/s; TIM17 used only as a cycle counter). It decimates 64 raw bits into one signed bit-density output (nominal ~86ksamples/s), calibrates actual samples/s from 2,048 outputs and timer cycles, then runs four separate 4,096-output windows. For each window, it records dual IQ-matched DFT amplitudes at **1kHz and 2kHz**, raw density RMS, mean high fraction, mean absolute density change, and RFIC VOX. The oscillator phase is calibrated to the measured DMA rate for this particular run. No UART/FD6818 bit-bang calls occur inside the active hot DMA loop; slow hardware calls occur between windows, when DMA is OFF. At any detected ring overrun, timer mismatch, missed route setup, missing old firmware service, PTT drop or cleanup error it aborts and records a *version7 error* rather than a false success. A successful four-window capture writes a CRC16-protected **version6** 33-byte MAB1 record, retrievable by live serial command0x86 after reconnecting the cable without rebooting; the existing reader `tools/k6_mic_result.py` was extended for v6/v7. No firmware reboot is needed between attended captures, provided the module is installed.

The stored 1kHz/2kHz amplitudes are **relative 8-bit normalized DFT scores**, not calibrated or reconstructed PCM. A significant rise in 1kHz when generator=1kHz, rise in 2kHz when generator=2kHz, and absence of both when OFF, with correspondingly high mic VOX, would justify further GP0-to-MCU speech work. A flat or noisy spectrum is evidence against this tested setting, **not proof that no undocumented mic route exists**. The exact digital GP0 selector12 content remains experimentally unknown. This probe is only a gate for an honest next step; it does not magically supply voice to Sotto without further modem work.

## Test gates and physical plan

- `tests/test_k6_sotto_mic_gp0_dma.py` runs the actual compiled C module under a fake FD6818, fake TIM17/DMA CNDTR, GPIOB IDR bitstream and 1kHz/2kHz/silence generator. It verifies frequency segregation, VOX, calibrated raw rate, clean exact GP0+TX teardown, CRC rejection, UART exclusion, older-firmware rejection, and busy-DMA refusal. ## First 8kHz GP0→PCM streaming building block (offline, no radio update)

The codec-facing conversion layer is now prototyped in `c/k6/mod/sotto_gp0_pcm.h`: stateful fixed-point 64-GPIO-bit population-count input from GP0 DMA, a measured-rate **fractional boxcar decimator from 84.96/87.77kHz to exactly 8kHz**, ~62Hz DC/bias high-pass, Q8 fractional amplitude to avoid 1-bit density quantization sticking, clipping counters and 16-bit signed PCM output. No floating point, system calls, malloc, hardware resources or libgcc division helper are required; the same C header cross-compiles for the actual Cortex-M0 loadable module target.

`tests/test_k6_sotto_gp0_pcm.py` and `tests/data/k6/sotto_gp0_pcm_host.c` exercise 2 seconds of synthetic 64-bit density data at four test rates (including both *physically measured* 84,960 and 87,770 samples/s) against silence/DC bias and 1kHz, 2kHz and 2.6kHz tones. It confirms **exactly 16,000 PCM samples** emitted per two-second input, 0 clipping and frequency-specific tone recovery with nonzero SNR after DC settling. A DC estimator rounding bug found in the first version created ~2,040 counts of false DC; fixed by keeping the IIR bias in Q16. All **18 tests pass**, including ARM PIC compilation and the signed 8kHz output contract. These are **synthetic model tests**; the only live hardware evidence so far is the narrowband 1kHz/2kHz GP0 DMA spectra above.

The immediate integration challenge is **continuity while Sotto encodes and transmits**. The current DMA1 ch1 on this chip runs free at ~5.5 million GPIOB bytes/s, and a 1024-byte circular buffer wraps in ~186µs. The original GP0 code must poll and consume data frequently, and the live Sotto codec may block the module loop much longer than that. A real-time solution needs an IRQ-fed decimator/PCM ring, a DMA capture offload with host buffering, a reduced effective GP0 sampling rate, or another architecture that preserves raw-bit continuity during codec execution. The standalone header by itself does **not** establish successful real-time encoder concurrency. The existing live `SOTTO MIC` slot30 continues using its old PA11 sampler, untouched. Do not silently replace it until the DMA/codec scheduler and real microphone PCM path are proven.

The next physical evidence upgrade can be a **slot25 PCM diagnostic** using this exact decimator and the RFIC-only op7 service, with its output 8kHz PCM amplitude, RMS, 1kHz/2kHz spectral bins and VOX saved in the existing mailbox. This does not require another base firmware flash. If 8kHz PCM is validated, integrate continuous ring production into the existing `sotto_live_engine.h` with a cycle/underrun gate and use the known-good independent RTL-SDR monitor to test actual audible voice. The base hardware mic→GP0 signal path is now validated via the three tone captures; the bottleneck has moved from physical wiring to capture/codec timing and SNR.
