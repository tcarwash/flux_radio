# Flux FSK-10 — physical 64-byte native-FSK frame qualification

Date: 2026-11-23. Branch: `research/offline-sotto-fsk-dv-20261123`.
This report follows the **precommitted** [FSK-10 L64 protocol](k6-fsk10-l64-physical-protocol-20261123.md), commit `228fefd` and the physical FSK-09 study. This is **native-FSK frame-size validation, not live Sotto speech** and not continuous FIFO streaming.

## Physical result: PASS, repeated

Two manually initiated, separate, guarded bench transactions on the confirmed dummy-loaded K6 / FD6818B 0x4829, known firmware `95d6b260d4122287`, 433.500 MHz, RTL-SDR IQ captured from 433.750 MHz center at 1.024 Msps. Both transactions used the **same process-scoped shared Flux `serial_lock('/dev/ttyUSB0')`** used by active TX16N work and held it during *radio mutation, keyed RF capture, restoration*. Neither forcibly acquired the lock. Each transmission was bounded to 1900ms firmware TX lease, with an independent RF watchdog and a single module invocation per transaction.

Exactly two 32-word (64-byte = 512-bit) FIFO payload frames were transmitted per transaction. The source uses `REG_5D=0x3f00`, normal `0xc194` 4,800-bps setting, and known distinct payloads. Both RF buffers were acquired **independently using only the first 256 training bits of their respective frames**, leaving 256 bits per frame held out from timing/level estimation.

The independently captured repeat has an equal quantized result at this decoder's approximately one native-bit-period timing resolution. This is a **two-adjacent-frame result in two repetitions**, not a long-run stability/BER study.

## Implications for Sotto packet DV

The existing L packet format is **64 bytes and includes eight Sotto 1200 6-byte/40-ms superframes = 320ms of compressed speech** plus header/padding/CRC. With an independent FSK-10 measurement now available, the `tools/k6_sotto_fsk_offline.py` model uses `RF_RESTART_S_L = 0.044375` (instead of previously borrowing XL's `0.046719`). The 15-second-sample no-loss model with 160ms jitter reserve now predicts an **~611ms capture-to-playout latency** (previously ~613ms), 47.33% nominal RF packet airtime, and 100% idealized deadline availability at up to 150ms extra latency. With depth2 XOR parity + 500ms buffer, estimated delay **~1,231ms** and nominal packet airtime 71.49%.

These are host transport-model estimates. They assume an independently recoverable radio frame and do **not** include real blind sync performance, long-run loss, dynamic PLL reacquisition, additional MCU scheduling, Sotto PCM encode/decode processing or actual microphone-to-ear latency.

## Next hardware gates

1. Physically transmit **actual Sotto-1200-containing L packet bytes** (with existing CRC/header/whitening) through the same safe short-frame module; separately decode and CRC-validate all received bytes. A known-pilot RF decoder can be used for the initial validation, but must not imply blind sync.
2. Verify receiver availability and independent packet acquisition under consecutive frames and realistic over-the-air quality, with perhaps 8–20 frames instead of two; avoid assuming a long run succeeds from two repeats.
3. Integrate real packet erasure feedback and bounded jitter buffer, then confirm acoustic output and encoder/decoder CPU cost on actual hardware.
4. Maintain independent FIFO-refill research (#7–#9) for genuinely continuous RF transmission. FSK-10 currently **rearms the hardware modem between frames**, and the 44.375ms interval is not payload data.

**Confirmed:** 2×64B known-payload frame transport twice, heldout 0/1024 bits across 4 frames, timing measurement, safe restoration and lock sharing. **Not confirmed:** continuous FIFO streaming, blind Sotto frame detection, full live voice or generic payload BER.
